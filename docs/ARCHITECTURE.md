# SafeKey V2 设计说明

## 系统结构

```text
K1/K2/K3 → STC-B 单片机 → CH340 串口 → Windows 主机程序
                                      ├─ 认证状态机
                                      ├─ AES-256-GCM 保险箱
                                      ├─ AES-256-GCM 保险箱
                                      ├─ 修改后重新加密保存
                                      └─ 临时明文目录生命周期管理
```

单片机负责 PIN 输入、失败次数限制、蜂鸣器/LED/数码管反馈和串口事件；主机负责保险箱加解密、文件操作和设备在线监控。

## 认证状态

```text
未连接 → 已连接 → 设备就绪 → PIN 认证成功 → 临时解锁
   ↑          └──────── PIN 错误/超时/拔出 ────────┘
   └────────────────────── 立即锁定
```

## V2 新增能力

- 保险箱格式从 `SAFEKEY1` 升级为 `SAFEKEY2`，同时兼容读取旧文件。
- 创建和保存采用临时文件原子替换，降低写入中断导致文件损坏的概率。
- 解锁目录可直接打开、修改，再重新加密保存。
- 解压拒绝路径穿越和符号链接，主机端测试覆盖正常往返和恶意路径。
- 支持保险箱完整性检查、修改检测和可配置自动锁定。
- 图形界面集中显示设备状态、保险箱条目数、载荷大小和自动锁定倒计时。
- 可通过 PyInstaller 打包成单文件 Windows EXE，面向最终用户隐藏 Python 命令行。

## 当前安全边界

V1.1 是课程原型，不是专业安全令牌。AES-GCM 能检测密文篡改，但设备密钥仍由主机程序管理，不能抵御主机被控制或密钥被提取的攻击。固定 `SKOK` 也仍然存在重放风险。V2 才引入随机挑战-响应；产品级方案应使用安全元件，而不是普通 EEPROM。

## 验收演示建议

1. 展示单片机输入 PIN 时不显示明文数字。
2. 连续三次错误后展示 30 秒锁定。
3. 正确认证后创建并解锁中文嵌套目录。
4. 修改保险箱字节，展示 AES-GCM 完整性校验失败。
5. 拔出学习板，展示临时明文目录自动清理。
6. 运行 `python -m unittest test_safe_key.py`，展示自动化测试结果。
7. 将自动锁定时间临时设置为 10 秒，展示超时后自动清理明文目录。
